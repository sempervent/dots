# DOTS v1.6 roadmap

Local-first agent orchestration. Phases are **release gates**, not parallel
wishlists. Do not start a later phase until the prior phase’s acceptance
criteria are met.

## Evidence labels

When describing Phase 1 (PR #24) status, use only:

| Label | Meaning |
|-------|---------|
| **PROVEN** | Exercised end-to-end with evidence (live or mocked as stated) |
| **CONFIGURED** | Files / merge / desired-state present; not fully runtime-proven |
| **MOCKED** | Covered by deterministic tests without paid / live providers |
| **DEFERRED** | Explicitly out of scope until a later phase |

## Phase 1 — Foundation (PR #24)

In scope:

```text
Pi
LiteLLM (localhost)
model-scout
expert consultation
budget + ledger
local-first harness
```

Closure criteria (summary):

- Runtime commands never surprise-install dependencies
- Model Scout status reports real executable / MCP / discovery state
- Pi can use the intended local model (provider + models.json + RPC)
- Pi discovers `dots-model-scout` and `dots-expert` (not JSON-only inference)
- LiteLLM uses a non-predictable master key
- Budget reserve/settle / failure accounting is deterministic
- Canonical mocked local→scout→expert→verify acceptance test is green
- No OpenRig, sandbox, evals, or multi-agent orchestration in this PR

## Phase 2 — Trust and isolation

Required before release:

```text
Pi sandbox / permission policy
safe filesystem boundaries
network policy
secret isolation
worktree/container execution
MCP Inspector integration (fuller DOTS developer-tool path)
```

Phase 1 may document an optional Inspector CLI path; persistent Inspector
services and policy enforcement wait for Phase 2.

## Phase 3 — Evidence-based routing

Required before release:

```text
dots agent eval
model capability benchmarks
task-class success history
expected-cost routing
quality-floor calibration
routing regression suite
```

Target selection concept:

```text
expected task cost =
    estimated request cost
    /
    estimated success probability
```

rather than merely cheapest token rate.

## Phase 4 — OpenRig orchestration

Required before release:

```text
first-class openrig component
native Pi runtime
Codex integration where available
Herdr terminal workspace integration
persistent teams
planner / builder / reviewer roles
shared task queue
agent handoff
restart/resume
```

Current OpenRig supports Pi natively — implement against current docs when
this phase starts. Not part of PR #24.

## Phase 5 — Autonomous escalation and release

Required before release:

```text
deterministic stuck/failure detection
automatic escalation policy
retry/backoff
resume/replay
cost telemetry
privacy controls
live system tests
release documentation
v1.6 release gate
```

## Stretch (not mandatory for initial v1.6)

Recorded separately so they do not delay the core release:

```text
multi-model voting
model debate
OpenRouter Advisor
full consensus/fusion
Claude component
remote distributed OpenRig workers
```

Promote into a numbered phase only by explicit decision.
